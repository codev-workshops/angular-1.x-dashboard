# Devin CLI Blitz Demo -- angular-dashboard Edition

**Duration:** 20 minutes (self-paced video)

**Demo Repository:** [`angular-1.x-dashboard`](https://github.com/codev-workshops/angular-1.x-dashboard) -- an AngularJS 1.x widget dashboard framework with drag-and-drop, resizing, and state persistence.

**What you'll learn:** Devin CLI basics, AGENTS.md and Skills for customizing agent behavior, MCP server connections, and handing off work to cloud Devin.

---

## Prerequisites

- Devin CLI installed (`curl -fsSL https://cli.devin.ai/install.sh | bash`)
- A Devin account (https://app.devin.ai)
- A cloned repo to experiment in

---

# Part 1 -- CLI Fundamentals (5 min)

### 1.1 -- Launch and explore

```bash
cd angular-1.x-dashboard
devin
```

```
/help
```

Ask Devin about the codebase:

```
What does this project do? Give me a 3-bullet summary.
```

> **Narrator:** "Devin reads the source -- `dashboard.js`, `WidgetModel.js`, `package.json` -- and summarizes: it's a drag-and-drop widget dashboard framework built on AngularJS, jQuery UI Sortable, and Bootstrap, with localStorage persistence."

### 1.2 -- Permission modes

| Mode | Command | What it does |
| --- | --- | --- |
| **Normal** (default) | `/normal` | Asks before writes |
| **Accept Edits** | `/accept-edits` | Auto-approves file edits |
| **Bypass** | `/bypass` | Auto-approves everything |

Switch to Accept Edits and make a change:

```
/accept-edits
Add a one-line comment to the top of the README explaining what this repo is.
```

> **Narrator:** "Devin edits the file directly -- no approval prompt. But it would still ask before running shell commands like `gulp build`."

### 1.3 -- Plan mode

```
/plan
How would you add a "locked widget" feature that prevents individual widgets from being moved or resized?
```

> **Narrator:** "Devin produces a plan referencing real files -- add a `locked` property to `WidgetModel.js`, hide resize handles in `dashboard.html`, persist via `serialize()`. Plan mode is great for thinking through a feature before writing code."

# Part 2 -- AGENTS.md & Skills (7 min)

### 2.1 -- AGENTS.md

> **Narrator:** "AGENTS.md is a 'README for agents' -- an open standard that gives Devin persistent context about your repo."

Copy this to the repo root as `AGENTS.md`:

```markdown
# AGENTS.md

## Project overview
AngularJS 1.x directive library (`ui.dashboard` module) for persistent,
draggable, resizable widget dashboards. Built with Gulp, tested with Karma + Jasmine.

## Commands
- Install: `npm install && bower install`
- Build:   `gulp`
- Lint:    `gulp jshint` -- ALWAYS run before committing
- Test:    `gulp test`

## Code conventions
- Source: `src/components/` (framework), `src/app/` (demo)
- AngularJS 1.x patterns only (`.directive()`, `.factory()`) -- no ES6 classes
- Data models extend `WidgetDataModel` via `Object.create`
- Follow `.jshintrc`: camelCase, single quotes, strict mode, 2-space indent
- Apache 2.0 license header on all new `.js` files

## Boundaries
- Never modify `dist/` directly -- generated by `gulp build`
- Don't remove Apache 2.0 license headers
```

**What makes this good:**

1. **Commands** -- exact build/lint/test commands so Devin stops guessing
2. **Conventions** -- concrete rules ("extend via `Object.create`"), not vague ("write clean code")
3. **Boundaries** -- explicit "never touch X" rules

Test it:

```
What conventions should I follow when adding a new data model?
```

### 2.2 -- Skills

Create `.devin/skills/pre-pr-check/SKILL.md`:

```markdown
---
name: pre-pr-check
description: Run the pre-PR quality gate before creating or updating any pull request.
---

# Pre-PR Quality Gate

Follow these steps in order. Do not skip steps.

1. Run `gulp jshint` and fix any lint errors.
2. Run `gulp test` and ensure all tests pass.
3. Review your diff with `git diff` and check for debug statements, commented-out code, and missing license headers.
4. Summarize the results.
```

Run it:

```
/pre-pr-check
```

> **Narrator:** "Skills become slash commands. But Devin also invokes them automatically -- ask 'get this branch ready for a PR' and it picks up the skill on its own."

# Part 3 -- MCP Connection (3 min)

> **Narrator:** "MCP -- Model Context Protocol -- gives Devin extra tools: issue trackers, databases, documentation APIs."

Add the DeepWiki MCP (free, no auth, public repos only):

```bash
devin mcp add deepwiki https://mcp.deepwiki.com/mcp
```

Config scopes:

| Scope | Flag | Shared? |
| --- | --- | --- |
| local (default) | `-s local` | No (gitignored) |
| project | `-s project` | Yes (committed) |
| user | `-s user` | No (personal) |

Use it:

```
Use DeepWiki to explain the architecture of https://github.com/public-apis/public-apis
```

> **Narrator:** "Your team can connect Jira, Datadog, PagerDuty -- anything with an MCP server."

# Part 4 -- Handoff to Cloud (5 min)

> **Narrator:** "When a task outgrows your laptop, hand it off to cloud Devin."

```
/handoff implement the locked widget feature you planned earlier and open a PR
```

The CLI packages your conversation context and git branch into a cloud session. Track it in the terminal or at https://app.devin.ai.

> **Narrator:** "This is the core workflow: explore locally, delegate long-running work to the cloud, review the PR when it's done."
